# Cross-runtime MCP environment projection

## Scope

- Apply one normalized MCP header and environment-variable contract to every
  Ciel workspace MCP launch adapter currently supported by the package:
  Claude, Codex, and Codex App Server.
- Keep credentials out of persistent workspace configuration and Codex command
  arguments by retaining environment-variable references where the client
  supports them.

## Evidence

- Wing's process environment contained `AINET_API_KEY` with length 75.
- Wing's active `.codex/config.toml` contained both Authorization and
  `X-AI-Net-Push = "off"`.
- `codex-mcp.json` was last written on 2026-08-08 and is not generated by the
  current package, so it is stale evidence and was excluded from the current
  launch-path diagnosis.
- Wing's workspace `config.json` had an empty `workspace_mcp.servers` object.
- OpenAI Codex's official `build_default_headers` implementation applies static
  headers first, then replaces them with non-empty environment-backed header
  values.
- Google Antigravity CLI 1.1.10, installed locally and on Wing at diagnosis
  time, exposes no `mcp` command or launch-scoped MCP configuration flag. Its
  official changelog adds user-level `mcp` commands in 1.1.16.

## Implementation

- Merge the `http_headers` and `headers` aliases during normalization rather
  than selecting one and discarding the other.
- Resolve HTTP headers with one precedence rule: static headers, then non-empty
  environment-backed headers, then a non-empty bearer-token environment value
  for Authorization.
- Pass the exact child-process environment snapshot into workspace MCP launch
  preparation for Claude, Codex, and Codex App Server.
- Reject unknown runtime names instead of silently serializing them as Codex.

## Runtime boundary

- The shared code path covers every runtime that Ciel currently exposes as a
  workspace MCP adapter: Claude, Codex, and Codex App Server.
- AGY 1.1.10 cannot be included honestly in this launch-scoped contract: its
  observed CLI has neither an `mcp` subcommand nor an MCP config launch flag.
  Google's 1.1.16 changelog adds user-level MCP commands, but that is a
  persistent user-config surface rather than Ciel's ephemeral workspace launch
  surface. No fake AGY projection or unsafe global-config overwrite was added.
