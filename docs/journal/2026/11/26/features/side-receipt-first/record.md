## 변경

기존 `/ca/work/api/v1/side`는 유지한다. `view=receipts`는 최신 15건부터 기존 커서로 조회하며 비필터 호출은 본문을 최대 16건 투영한다. `view=summary`는 영수증 목록 렌더링과 별도로 검수·인계·전달 및 집계를 반환한다. 이전 영수증 추가와 필터 변경은 검수·인계 초안을 다시 렌더링하지 않는다. 영수증 파일 메타데이터 열거와 정렬은 그대로다.

## 증거

- 변경 전 회귀 테스트에서 영수증 전용 요청까지 보드 투영을 호출해 실패. 변경 후 통과.
- Windows 격리: Edge 브라우저 포함 26건 통과. 기존 Linux py310/py311: 각각 25건 통과, 브라우저 1건 스킵(브라우저는 Windows에서 검증).
- 합성 영수증 500건, 동일 15건 요청(격리 HTTP 테스트 서버): 첫 응답 기존 4,282.6ms / 영수증 전용 170.8ms, 다음 호출 137.0ms / 40.0ms. 부가 응답의 첫 호출은 별도 4,210.5ms. 이 수치는 운영 환경 성능을 보장하지 않는다.
- [브라우저 캡처](evidence/receipts-first.png): 부가 응답을 보류한 상태에서 최신 영수증과 추가 페이지가 이미 표시된다. 브라우저에서 상세 보기와 필터 전환 시 초안 유지도 확인했다.

운영 반영 및 재시작 없음.
