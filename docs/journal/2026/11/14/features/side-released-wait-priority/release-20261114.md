# Not active in this build

These are open work, not shipped behavior:

1. No producer creates a boost row. `side_work_decision.apply` clears the exact wait but does not set a blocked leaf to `pending` and does not write the recovery receipt or sidecar row from [the design](/design.md).
2. The reserve path (`_reserve_assignment`) does not read the sidecar, so released waits get no queue priority.
3. No JS host code calls the `wait_boost_*` events (L5).
4. Menu, web and ctl do not render the `wait_boost` block; only the model and public projections carry it (always `reason: none` now).
5. P0: nothing in the product calls `activate_root` (`work_priority_service.create_p0_root` is a stub), and the pump spawns with its own name rather than the backend `dispatch_name`. P0 is therefore unreachable in this build.

# Incident: accidental ruff fix over scratch

At 2026-11-14T21:44Z, a staging command produced an empty path list, so `ruff check --select F401 --fix` ran over the whole worktree, including `.local`. It rewrote 3,881 `.py` files.

- Nine product files were meant to receive exactly this fix, and they keep it.
- 3,552 files were restored byte-exactly. A candidate original was accepted only if running the identical fix over it reproduced the current bytes. Candidates came from untouched trees, git blobs and transcript Write inputs. No file had more than one matching original.
- After the restore, 410 snapshot manifests verify fully. Seventeen manifests still mismatch, but none of their mismatching files was touched by this run, so those mismatches existed before it.
- 320 files could not be restored. Of these, 278 are copies of Claude's marketplace cache in E2E config dirs; the rest are scratch probes. Each differs from its original only by the removed unused-import lines. They are listed in [the summary](/evidence/release-20261114/ruff-accident-summary.json).

The tools used are kept beside the summary: [restore](/evidence/release-20261114/restore_ruffed.py), [statement split](/evidence/release-20261114/split_statements.py) and [cycle scan](/evidence/release-20261114/import_sccs.py).
