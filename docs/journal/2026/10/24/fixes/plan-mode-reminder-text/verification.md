# Problem (observed)

In the local `ciel-code` session (router 9464, `glm-5.3-flash` on `ollama-cloud`), all 9 empty or reasoning-only turns between 14:43 and 16:30 were `ExitPlanMode` calls that the router dropped. Each one logged `dropped ExitPlanMode while plan mode is not active`. Diagnosis: [/2026/10/24/diagnostics/ciel-code-plan-exit-drop/finding.md](/2026/10/24/diagnostics/ciel-code-plan-exit-drop/finding.md).

- `plan_mode_active` only read `EnterPlanMode`/`ExitPlanMode` tool history and attachment objects. Claude Code never sends attachment objects on the wire.
- Native compaction removed the `EnterPlanMode` result while Claude Code stayed in plan mode.

# Change

`protocols/conversation_turn_policy.py`: `plan_mode_active` also follows Claude Code's own reminder texts, in message order. The texts come from the attachment builders in the shipped 2.1.310 binary:

| State | Text at line start |
|---|---|
| active | `Plan mode is active. The user indicated that they do not want you to execute yet` |
| active | `Plan mode still active (see full instructions earlier in conversation)` |
| active | `## Re-entering Plan Mode` + `You are returning to plan mode` |
| inactive | `## Exited Plan Mode` + `You have exited plan mode.` |

Where the texts are read:
- `system`-role messages, which is where 2.1.310 puts them.
- `<system-reminder>` sections of user text blocks (older versions).

What is never read:
- tool results, typed or pasted user text, assistant text;
- mentions in the middle of a line;
- restored file contents with line-number prefixes.

Tool history and attachment objects work as before. The `ExitPlanMode` drop itself is unchanged; it now sees the real state.

# Limits

- The reminder texts are matched literally. A future Claude Code wording change would bring the old behaviour back for sessions that have no `EnterPlanMode` history.
- The ciel-code session itself was not restarted. It keeps the old code until it restarts.
- The real GLM model was not used; the E2E uses a fake Ollama with a fixed `ExitPlanMode` reply.
